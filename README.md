# 班級點數系統：獨立前端

此倉庫僅包含靜態前端與原有美術素材，不包含學生名單、成績、附件、帳密、登入權杖、試算表或後端憑證。

目前以原有 V3.18 功能為基礎。GAS 原網站可保留；獨立前端透過另一個 API 部署讀寫同一份資料。

## 目前狀態

前端已完成連線介面，但 `config.js` 的 `apiUrl` 尚未設定。在設定正確的新 API 部署前，頁面會提示未連線，不能實際登入或保存資料，也不會假裝保存成功。

## 啟用 GitHub Pages

倉庫 Settings → Pages → Build and deployment → Source 選 Deploy from a branch，Branch 選 main、資料夾選 /(root)，儲存。
網站預期入口：https://peitt1940-creator.github.io/classroom-points/
需以 GitHub Pages 設定顯示的正式網址與部署狀態為準。

## 連接後端

1. 另行取得配套的 `ApiBridge.gs`（不存於本公開倉庫）。
2. 在原本綁定試算表的 Apps Script 專案中新增 ApiBridge 腳本，貼上配套程式。不要刪除原有程式或 Index.html。
3. 建立「新的網頁應用程式部署」，由擁有者執行，允許「任何人」存取。不要編輯或刪除原部署。若學校帳戶不允許匿名存取，先停止這一步；需改採經授權的伺服器轉接方式。
4. 將新部署 `/exec` 網址填入 `config.js` 的 `apiUrl`。這是公開API位置，不是帳密；不要放入任何秘密金鑰。
5. 先用獨立測試帳號確認登入、讀取、提交、附件、教師審核、金牌與寵物同步，再讓少數學生試用。最後才考慮擴大使用。

API 使用系統自己的帳密及短期登入權杖，連線不附帶瀏覽器的 Google 登入 cookie。原有 GAS 網址保留，不必立即通知全班換網址。

## 驗證範圍與限制

- 已完成本機前端編譯、API白名單、角色／帳號驗證、登入節流、前端連線與錯誤處理模擬。
- 未設定真實API URL，尚未完成正式環境的跨站連線、附件與多Google帳號驗證。
- 瀏覽器會直接向GAS API發送跨站請求。部署權限、Google重導與瀏覽器跨站限制可能仍使請求失敗；不能只因首頁能開就宣稱解決多帳號問題。
- 不使用 `no-cors` 假裝成功、不使用JSONP傳送學生資料，也不自動重送寫入請求。
- 逾時不等於未保存；請先重新讀取紀錄確認，再決定是否重送。
- 登入權杖僅留在記憶體，重新整理須重新登入。
- 系統仍受 Apps Script、試算表與Google服務的配額及使用政策限制。

## 維護

修改功能時應同步維護原GAS前端與此倉庫的前端。不要把後端完整程式、真實測試資料、錯誤回報中的個資或任何密碼推送到GitHub。
