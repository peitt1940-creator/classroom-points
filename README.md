## 開啟網站

倉庫 Settings → Pages → Build and deployment → Source 選 Deploy from a branch；Branch 選 main，資料夾選 /(root)，儲存。以設定頁顯示的正式網址與部署結果為準。

## 連接後端

使用另附的「classroom-points_backend_setup.zip」，不要上傳該壓縮包或真實設定到 GitHub。

1. 建立新的獨立 Google Apps Script 專案，加入配套 `Backend.gs`、`ApiBridge.gs`。此套 API 專案不需要 Index.html，不要將檔案貼進原 GAS 專案。原網站繼續保留。
2. 在新專案的指令碼屬性設定 `CLASSROOM_SPREADSHEET_ID` 與 `CLASSROOM_FOLDER_ID`。先指向複製的測試試算表及專用測試附件資料夾，帳號與資料全部使用虛構資料。
3. 授權後建立新的網頁應用程式部署，由擁有者執行，允許任何人存取。應用層仍會驗證登入與角色。若帳戶政策不允許匿名部署，停止此步並更換經授權的後端方案。
4. 將部署產生的 `/exec` 網址填入 `config.js` 的 `apiUrl`。該網址是公開 API 位置，不能在網址或 config.js 加入任何密鑰。
5. 完成下列實測後才指向正式資料。新後端會建立／修改資料表，不會自動替正式資料建立備份。原 GAS 程式與網址不會被改寫。

附件沿用指定資料夾的既有權限，不會自動開啟匿名連結分享。教師需確認資料夾沒有公開權限，並依實際需要授予合法使用者存取。登入系統本身不會賦予 Google Drive 檔案存取權。

## 已完成的驗證

- JSX 編譯與 JavaScript 語法檢查。
- 未連線、未登入與登出後拒絕受保護操作；登入頁依教師設定公開前三名的 Name 與總積分，後端限制最多三筆且僅回傳這兩個欄位。完整榜單、帳號與明細仍需登入。
- API 功能白名單、學生／教師／管理員分權、由伺服器確認提交身分。
- 後端只有 doGet/doPost 對外，實作函式以底線結尾，禁止 GAS 客戶端 RPC 直接呼叫。
- 移除原版離開 GAS 就進入的模擬成功分支。
- 移除圖片內嵌的中繼資料；公開檔案不含正式資料、資料夾 ID 或帳密。

## 尚待正式環境驗證

已取得並設定 API 部署網址，尚未完成真實環境端對端驗證。需使用虛構帳號測試：三種角色登入、分數申請及修改、教師審核／批次發放、公告定向與已讀、任務提交與獎勵防重複、寵物重新登入與 XP、金牌、濃縮紀錄、PDF 結算，以及手機、多 Google 帳號和附件權限。

GAS 的跨站重導、帳戶政策、配額或 CORS 可能阻擋請求；首頁能開不代表後端已可用。不使用 no-cors、JSONP 或自動重送寫入請求。連線失敗或逾時後，先重新讀取確認結果，再決定是否重送。

登入權杖只保存在記憶體，重新整理需要登入。原系統的帳密格式仍沿用 Users 表，尚未改為雜湊密碼；須限制試算表編輯及分享權限，使用獨立且不重複的系統密碼。登入節流為按帳號、快取式限制，不等同防火牆或完整防暴力破解方案。原 GAS 網站的舊安全風險不會因新增此網站而自動消失。

前端仍使用外部 React、Tailwind 與圖示 CDN；React 固定為 18.3.1。後續可評估自託管依賴。此版本未經外部滲透測試，不能宣稱絕對安全。
